# Database Schema Reference

## Overview

The project uses Supabase (PostgreSQL) as its data store with two primary tables: `expenses` and `income`. The schema is defined in `data/setup.sql`.

## Tables

### `expenses`

Stores all expense transactions.

| Column | Type | Constraints | Description |
|---|---|---|---|
| `id` | BIGINT | PRIMARY KEY, GENERATED BY DEFAULT AS IDENTITY | Auto-incrementing unique identifier |
| `amount` | DECIMAL(12, 2) | NOT NULL, CHECK (amount > 0) | Positive monetary amount |
| `category` | TEXT | NOT NULL | Expense category (food, transport, etc.) |
| `description` | TEXT | | Brief description of the expense |
| `date` | TIMESTAMPTZ | DEFAULT NOW() | Timestamp of the transaction |
| `type` | TEXT | DEFAULT 'expense' | Redundant but explicit type field |

**Category Values:**
- `food`, `transport`, `entertainment`, `utilities`, `healthcare`, `shopping`, `education`, `other`

### `income`

Stores all income transactions.

| Column | Type | Constraints | Description |
|---|---|---|---|
| `id` | BIGINT | PRIMARY KEY, GENERATED BY DEFAULT AS IDENTITY | Auto-incrementing unique identifier |
| `amount` | DECIMAL(12, 2) | NOT NULL, CHECK (amount > 0) | Positive monetary amount |
| `source` | TEXT | NOT NULL | Income source (Salary, Freelance, etc.) |
| `description` | TEXT | | Additional details |
| `date` | TIMESTAMPTZ | DEFAULT NOW() | Timestamp of the transaction |
| `category` | TEXT | DEFAULT 'income' | Always 'income' |
| `type` | TEXT | DEFAULT 'income' | Always 'income' |

## Setup

Run the SQL script in the Supabase SQL Editor:

```bash
# File: data/setup.sql
psql -h <supabase-host> -U postgres -d postgres -f data/setup.sql
```

Or paste the contents directly into the Supabase dashboard SQL editor.

## Repository Layer

The repository pattern abstracts database operations behind a Protocol interface:

```python
class TransactionRepository(Protocol):
    def add(self, transaction: Transaction) -> Transaction: ...
    def list_all(self) -> List[Transaction]: ...
    def list_by_type(self, transaction_type: TransactionType) -> List[Transaction]: ...
    def list_by_category(self, category: TransactionCategory) -> List[Transaction]: ...
    def list_by_date_range(self, start_date, end_date) -> List[Transaction]: ...
    def total_amount(self, transaction_type) -> float: ...
    def clear(self) -> None: ...
```

### Implementations

- **SupabaseExpenseRepository** — operates on the `expenses` table
- **SupabaseIncomeRepository** — operates on the `income` table

Both extend `BaseSupabaseRepository` which handles Supabase client initialization and domain mapping.

## Domain Mapping

Database rows are mapped to `Transaction` domain models:

```python
# Database row → Domain model
Transaction(
    id=row["id"],
    amount=row["amount"],
    type=TransactionType.EXPENSE,  # or INCOME
    category=TransactionCategory(row["category"]),
    description=row.get("description") or row.get("source", ""),
    date=datetime.fromisoformat(row["date"])
)
```

## Indexing Recommendations

For production workloads, consider adding indexes:

```sql
-- Category-based queries
CREATE INDEX idx_expenses_category ON expenses(category);

-- Date range queries
CREATE INDEX idx_expenses_date ON expenses(date DESC);
CREATE INDEX idx_income_date ON income(date DESC);

-- Composite queries (category + date)
CREATE INDEX idx_expenses_category_date ON expenses(category, date DESC);
```

## Data Integrity

The Data Engineer Agent (`agents/data_engineer.py`) provides integrity validation:

- Checks for negative amounts in income records
- Flags negative amounts in expense records (possible refunds)
- Validates schema structure via `information_schema` queries

## Connection Modes

The project supports two connection modes:

1. **REST API (Supabase client)** — used by Finance/Strategy agents via `supabase` Python SDK
2. **Native PostgreSQL (asyncpg)** — used by Data Engineer agent for direct SQL execution

For native connections, set `SUPABASE_DB_URL` in your `.env`:

```
SUPABASE_DB_URL=postgresql://postgres.<project>:<password>@aws-0-<region>.pooler.supabase.com:6543/postgres
```
